# Аналитика в админке

Раздел `/admin` → «Аналитика» читает настоящие отчёты существующего счётчика
Яндекс.Метрики **111146201**. Отдельная база, миграции и service-role ключ Supabase
не нужны. Ранее собранная статистика доступна после подключения API.

## Подключение на Timeweb

1. Получите OAuth-токен под аккаунтом Яндекса, у которого есть доступ к этому
   счётчику. Создайте приложение «Для доступа к API или отладки» с **metrika:read**:
   [официальная инструкция](https://yandex.ru/dev/metrika/ru/intro/authorization).
   Право `metrika:write` не требуется.
2. В переменных окружения приложения Timeweb добавьте:

   ```dotenv
   METRIKA_OAUTH_TOKEN=<токен Яндекса>
   METRIKA_ADMIN_EMAILS=<email входа владельца в админку>
   METRIKA_COUNTER_ID=111146201
   ```

   Email должен совпадать с email пользователя Supabase Auth. Несколько владельцев
   указываются через запятую. Без списка доступ к отчётам закрыт даже авторизованным
   пользователям. Переменные `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY`, необходимые
   для существующей админки, также должны быть настроены.

3. Перезапустите приложение / выполните деплой ветки с изменениями. Откройте
   админку, войдите и выберите «Аналитика». Нажмите «30 дней»: должны появиться
   реальные отчёты. Нулевой трафик отображается как нулевой, а ошибки API — как
   ошибки, без подмены демонстрационными значениями.

Токен не отправляется в браузер, не сохраняется в localStorage, не коммитится.
Не задавайте ему имя с префиксом `VITE_`. Не присылайте токен в чат.

## Цели обращений

В Метрике → Настройка → Цели создайте тип **JavaScript-событие** с условием
«совпадает» и соответствующим идентификатором:

| Название              | Идентификатор      |
| --------------------- | ------------------ |
| Открытие бронирования | `booking_open`     |
| Клик по телефону      | `contact_phone`    |
| Переход в WhatsApp    | `contact_whatsapp` |
| Переход в Telegram    | `contact_telegram` |
| Переход в VK          | `contact_vk`       |

Обработчик контактов общий для окна бронирования, плавающего меню и футера.
Код отправки событий уже подключён. Цели автоматически читаются через API;
показываются первые 10 целей счётчика (до 20 метрик в запросе). Если на счётчике
есть другие цели, сначала проверьте список. Колонка «Достижения» — число
срабатываний, конверсия — доля визитов с достижением конкретной цели.
Открытие окна и клик в мессенджер не подтверждают отправку сообщения и аренду.
Историю новых целей задним числом восстановить нельзя.

## Как различать рекламу и мессенджеры

Размещайте разные ссылки в каждом канале. Например:

```text
https://gameplay-nalchik.ru/?utm_source=avito&utm_medium=classified&utm_campaign=profile
https://gameplay-nalchik.ru/?utm_source=telegram&utm_medium=social&utm_campaign=channel
https://gameplay-nalchik.ru/?utm_source=vk&utm_medium=social&utm_campaign=profile
https://gameplay-nalchik.ru/?utm_source=instagram&utm_medium=social&utm_campaign=bio
```

Без меток приложения иногда не передают referrer, и визит попадает в прямые
переходы. Для источников используется атрибуция «Последний переход».

## Отчёты и ограничения

- Визиты, уникальные посетители за период, просмотры, отказы, среднее время.
- Динамика по дням, источники / поисковики / соцсети, UTM source / medium /
  campaign, города, устройства, страницы входа, внешние домены переходов.
- До 100 строк в таблицах: интерфейс сообщает, если есть ещё строки.
- Период до 366 дней, московское время; кэш на сервере 60 секунд, ошибки 15 секунд.
- Ошибки отдельных отчётов не скрывают остальные данные. Запросы ограничены тремя
  одновременно, общий кэш ограничен 30 периодами. Есть таймаут внешнего API.
- Скрипт запускается только после согласия на аналитику. Блокировщики, отказ от
  согласия и задержка обработки Метрики влияют на числа. Устройства и города
  определяет Метрика, личности посетителей не раскрываются.
- Прямые загрузки админки не инициализируют счётчик; переходы и события внутри
  `/admin` не отправляются. В отчётах исключены визиты со входом через `/admin`.
  Исторические просмотры админки внутри обычного визита могли сохраниться в
  старых данных. Вебвизор существующего счётчика этим изменением не перенастраивается.

## Проверка после выкладки

1. Под владельцем открыть отчёт; под пользователем вне allowlist запрос должен
   вернуть отказ в доступе. Токена Яндекса в сетевых ответах и клиентском JS нет.
2. В приватном окне без блокировщика открыть одну из UTM-ссылок, принять аналитику,
   перейти в игры и нажать контакт. Отправлять сообщение не нужно.
3. В Метрике проверить визит и события после обработки данных; затем обновить
   отчёт админки. Не проверять сбор из `/admin`.
4. При отклонённой аналитике новых событий счётчика быть не должно.

Локальные проверки: `npm run lint`, `npm run typecheck`, `npm run build`,
`node --test tests/metrika.test.mjs` (Node 22.18+ / 24). Тесты используют mock API,
не настоящий токен и не действующий счётчик.
