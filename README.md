# GamePlay Нальчик

Сайт проката игровых приставок PlayStation в Нальчике — [gameplay-nalchik.ru](https://gameplay-nalchik.ru).

Лендинг с каталогом приставок, библиотека игр с поиском и фильтрами и админка,
через которую владелец сам ведёт каталог: добавляет игры, грузит обложки,
расставляет порядок карточек.

## Стек

- **TanStack Start** (React 19, SSR) + TanStack Router — маршруты описаны файлами в `src/routes`
- **TanStack Query** — загрузка каталога на клиенте
- **Tailwind CSS v4** + shadcn/ui (`src/components/ui`), тема задана переменными в `src/styles.css`
- **Supabase** — таблица `games` и бакет `game-images`, авторизация админа
- **Vite** + Nitro, пресет `node-server` (см. `vite.config.ts`)

## Запуск

```bash
npm install
npm run dev
```

Нужны переменные окружения (файл `.env` в корне, в репозиторий не коммитится):

```
VITE_SUPABASE_URL=https://<project>.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=<publishable key>
# Те же значения без префикса VITE_ читает серверная часть (SSR, серверные функции):
SUPABASE_URL=https://<project>.supabase.co
SUPABASE_PUBLISHABLE_KEY=<publishable key>
```

Ключ publishable (anon) не секретный — он и так уезжает в браузер. Секретов в
репозитории нет и быть не должно: всё остальное задаётся в переменных окружения
хостинга.

Timeweb напрямую из репозитория.

```

  index.tsx            главная (hero, приставки, превью игр, FAQ, отзывы)
  games.tsx            полная библиотека игр: поиск + фильтр по категориям
  admin.tsx            админка: вход, CRUD игр, загрузка обложек, порядок карточек
  privacy-policy.tsx   политика конфиденциальности
  terms.tsx            пользовательское соглашение
  sitemap[.]xml.ts     sitemap
  api/public/game-image/$.ts   прокси обложек из Supabase Storage
src/lib/
  games.functions.ts   серверные функции: чтение каталога и все админские мутации
  game-display.ts      подписи стикеров/категорий и путь к обложке (общее для страниц)
  image-compress.ts    сжатие фото в браузере перед загрузкой

```

## Данные и доступ

Каталог — одна таблица `games`: название, обложка, стикеры, категории, позиция в
списке и поля для окна подробностей (жанр, число игроков, описание, язык
озвучки и интерфейса). Допустимые значения проверяются zod-схемами в
`src/lib/games.functions.ts`, ограничений на уровне БД нет.

Чтение каталога публичное (anon-ключ, RLS разрешает SELECT). Все изменения идут
через серверные функции с middleware `requireSupabaseAuth`: он проверяет
Bearer-токен Supabase Auth и отдаёт клиент, ограниченный RLS. Service-role-ключ
в приложении не используется.

### Что стоит держать в голове

- **Политики Storage и права на запись в `games` заведены в панели Supabase, а
  не в миграциях.** В `supabase/migrations` есть только публичный SELECT, поэтому
  по одному репозиторию новый проект Supabase не поднимется — админка не сможет
  ни писать в таблицу, ни грузить обложки. Перед переездом снимите актуальные
  политики из дашборда и положите их сюда миграцией.
- **Регистрация в Supabase Auth должна быть выключена.** Права на изменение
  каталога привязаны к роли `authenticated`, то есть к любому подтверждённому
  пользователю проекта, а не к конкретному админу. Если открыта публичная
  регистрация — каталог сможет править кто угодно.
- **Статистику собирает Яндекс.Метрика** (счётчик 111146201, задан в
  `src/lib/analytics.ts`). Скрипт подключается только после нажатия «Принять» в
  баннере о cookie, до этого не грузится вовсе. Переходы внутри сайта идут без
  перезагрузки, поэтому просмотр страницы отправляется вручную из `__root.tsx`.
  Google Analytics отключён: `GA_MEASUREMENT_ID` пустой.
